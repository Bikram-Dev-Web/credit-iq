# Deploying the public demo

The hosted demo is the API on **Render** (free plan), Postgres on **Neon** (free), and the dashboard on **Vercel**
(free). It serves the **synthetic** model, and admin actions are switched off. MLflow, Prometheus and Grafana run
only locally (`docker compose up`); see [ADR 12](adr/0012-deployment-targets.md).

Everything below needs your own accounts. It takes about 30 minutes, and none of it costs money.

## 0. Push the repository to GitHub

```bash
cd creditiq-v2
git remote add origin https://github.com/<you>/creditiq.git
git push -u origin main
```

CI starts on the first push (Actions tab). The `images` job publishes Docker images to GitHub Container Registry.

## 1. Postgres on Neon

1. Sign up at <https://neon.tech> → **New project** (any region near your Render region).
2. Copy the connection string from **Dashboard → Connection details** (it looks like
   `postgresql://user:pass@ep-xxx.region.aws.neon.tech/neondb?sslmode=require`). The API converts the scheme to the
   psycopg driver itself, and creates its tables on start-up (Alembic migrations).

## 2. API on Render

1. Sign up at <https://render.com> with GitHub → **New → Blueprint** → choose the repository. Render reads
   [`render.yaml`](../render.yaml) and proposes the `creditiq-api` web service (Docker, free plan).
2. Fill in the environment variables it asks for:
   - `DATABASE_URL`: the Neon string from step 1.
   - `API_KEYS`: `analyst:<a long random string>` (generate one with `python -c "import secrets;
     print(secrets.token_urlsafe(32))"`). **Do not add an admin key on the public demo.**
   - `CORS_ORIGINS`: your Vercel URL from step 3 (you can add it later and redeploy).
   - `AUDIT_HASH_KEY` is generated by Render.
3. **Apply**. The first build trains the synthetic models inside the image (about 5–8 minutes). When it is live,
   check `https://<service>.onrender.com/readyz` (`"status": "ready"`) and `…/docs` (interactive API docs).

Free Render services sleep after 15 minutes without traffic. The first request after that takes 30–60 seconds.

## 3. Dashboard on Vercel

1. Sign up at <https://vercel.com> with GitHub → **Add New → Project** → import the repository.
2. **Root Directory:** `web`. The framework preset is detected as Next.js; pnpm is picked up from `packageManager`.
3. **Environment variables** (Production):
   - `CREDITIQ_API_URL` = `https://<service>.onrender.com`
   - `CREDITIQ_ANALYST_KEY` = the analyst key from step 2
   - `NEXT_PUBLIC_ENVIRONMENT` = `demo`
   - leave `CREDITIQ_ADMIN_KEY` **unset** (this hides admin actions)
4. **Deploy**. Then put the Vercel URL into Render's `CORS_ORIGINS` (step 2) and redeploy the API.

The browser only ever talks to Vercel; the Next.js server adds the API key when it calls Render, so the key is not
exposed.

## 4. Scheduled checks (optional)

Repository → **Settings → Secrets and variables → Actions**:

- `DEMO_API_URL` = `https://<service>.onrender.com`
- `DEMO_ANALYST_KEY` = the analyst key

The *Scheduled monitoring and retraining* workflow then wakes the API every day and runs a drift check, so the
Monitoring page on the demo shows real runs and alerts. The weekly retrain uploads a candidate model as a workflow
artifact; it never promotes.

## 5. Link the demo in the README

Replace the *Live demo* placeholder at the top of the [README](../README.md) with your Vercel URL.

## Seeding demo traffic (optional)

To fill the decisions log and overview trend on the hosted demo:

```bash
uv run python scripts/seed_demo.py --api https://<service>.onrender.com --key <analyst key> --rows 300
```
